# 研记来电：卓易通兼容性检查

## 2026-09-17 真机反馈

用户在鸿蒙手机的卓易通内安装 Claude Link 0.3.20：来电通知能够收到；“测试手机震动”没有物理振动；“测试来电铃声”使原有媒体停止，但没有可听铃声。截图确认卓易通内允许通知、铃声和振动已开启，静默通知已关闭，横幅通知未开启。

这些结果不证明所有卓易通版本都不支持声振，也不证明音频焦点具体在哪里发生变化。Android API 不抛异常不能替代真机验收。

## 公开资料能证明什么

- [AHA 开发方的卓易通安装说明](https://www.ahaspeed.com/zh-hans/faqs/harmonyos-next-chunxuehongmeng-ruhexiazai-aha-jiasuqi) 记录过安卓版在卓易通内持续响铃/震动，并要求到“卓易通 → 我的 → 应用管理 → 对应应用 → 通知管理”关闭。它支持通知提醒路径在部分环境实际可用；未公开直接振动或铃声 API 的实现。
- [华为：优先通知相关问题](https://consumer.huawei.com/cn/support/content/zh-cn16085150/) 第 6 项说明卓易通暂不支持鸿蒙“优先通知”。这指通知排序能力，不能解释为所有通知或全屏来电均不支持。
- [Android Ringtone 源码](https://android.googlesource.com/platform/frameworks/base/+/refs/heads/main/media/java/android/media/Ringtone.java) 中 `play()` 无成功返回值，资源、远端播放器或音量问题可能只记日志。因此 0.3.20 的系统默认铃声 URI 路径不足以诊断无声。

## 0.3.21 检查步骤

1. “测试普通通知”三秒后发出一个有声音/振动配置的普通通知，不调用应用的直接播放器和 Vibrator。此项验证卓易通通知转发；观察前台及回到桌面后的实际反馈。
2. “测试内置来电铃声”和“测试兼容铃声（媒体音量）”播放完全相同的应用内 WAV，分别使用 RINGTONE 和 MEDIA 用途，三秒后释放。它们显示 prepared/error、isPlaying、播放位置、输出设备和各类音量。
3. “测试直接震动”报告服务、hasVibrator、设备列表与异常。“查看详细诊断”内的按键触感测试用于区分交互触感与来电震动。
4. 复制诊断结果并附上每项的实际听感/振感。报告不含连接地址、配对码、API 密钥、设备唯一标识或录音。

解释结果时：普通通知声振可用，不代表直接振动 API 可用；媒体音源可听而来电用途无声，才支持继续调查用途/音量/路由映射；播放位置递增仍不是扬声器已出声的证明。

实际来电使用内置 WAV 的 RINGTONE 用途，尊重通知渠道、静音和勿扰。MEDIA 仅作为用户主动点击的诊断测试，不自动用于来电。拒接/接听/超时后停止提醒，断网情况下也有本地五分钟上限并撤销来电通知。

内置 WAV 由 `tools/generate_yanji_ringtone.mjs` 生成，为 24 kHz 单声道 PCM16 的两秒双音片段。编译、解码和签名检查不能证明卓易通的实机效果。
